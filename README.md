## Запуск

Нужен Node.js 24 (проверено: 24.19.0), npm 11.

```sh
cd /workspace/Site_shop_work/site
npm ci
npm run dev -- --hostname 0.0.0.0
```

Работайте в существующей копии проекта. Дополнительный git worktree не нужен.
Проверки: `npm run lint`, `npm test`, `npm run build`. Производственный запуск: `npm start -- --hostname 0.0.0.0` после сборки.

## Заявки

Telegram и телефон доступны без подключения базы.
Форма не имитирует успешную отправку. До подключения сервисов и утверждения политики сервер отвечает 503; пользователю предложена прямая связь через Telegram.

1. Создайте проект Supabase. Выполните `supabase/leads.sql` через SQL Editor. RLS включён, публичных политик нет.
2. Скопируйте `site/.env.example` в `site/.env.local`. Этот файл исключён из Git. Заполните URL Supabase и серверный secret (`sb_secret_…`) или старый `service_role`, не публичный ключ. Используется только сервером.
3. Создайте бота через @BotFather, откройте своего бота и нажмите Start. Сохраните токен в `TELEGRAM_BOT_TOKEN`. Выполните `npm run telegram:chat-id` из `site/`, сохраните нужное число в `TELEGRAM_CHAT_ID`. Не отправляйте токены в чат.
4. Укажите реального оператора данных и контакт в `OWNER_NAME`, `OWNER_CONTACT`. Перед публичным сбором данных доработайте `app/privacy/page.tsx`: реквизиты, сроки хранения, основания, порядок удаления, перечень получателей и трансграничную передачу под фактическую организацию. Проверьте документ с юристом. Флаг не заменяет проверку документа.
5. После подключения и утверждения документа выставьте `LEAD_INTAKE_ENABLED=true`. Перезапустите сервер; для production пересоберите сайт. Отправьте тестовую заявку, проверьте Supabase и Telegram. Не считайте внешнюю интеграцию проверенной до этого.

Оба канала вызываются независимо. Успех означает получение хотя бы одним каналом, а сбой второго отмечается в серверном логе без данных заявки и ключей. Таймауты каналов — 8 секунд. Есть серверная валидация, honeypot и ограничение 5 запросов за 10 минут на адрес в рамках одного процесса. Для публичного высоконагруженного запуска настройте ограничение на стороне хостинга: память процесса не является распределённой защитой. Только доверенный прокси должен задавать заголовки IP.

Для сети нужны `api.telegram.org` и точный домен вашего проекта Supabase, например `<project-ref>.supabase.co`. Не отключайте TLS-проверки.

## Публикация

Исходники подготовлены; в интернет сайт автоматически не опубликован. При импорте в Vercel выберите Root Directory `site` и перенесите значения окружения через защищённые настройки. Для коммерческого сайта тариф Vercel Hobby не подходит: используйте Pro либо другой хостинг по выбору владельца.

После выбора домена задайте HTTPS-адрес `SITE_URL` и пересоберите сайт. Тогда появятся абсолютные canonical, Open Graph и sitemap. Без реального домена sitemap намеренно пуст, чтобы не публиковать выдуманные адреса. OG-файл уже подготовлен: `site/public/og.png`.

Название «Маркетинговый консалтинг» — рабочее. Цены, сроки, гарантии, состав команды, кейсы и отзывы не придуманы. Структура процесса и тон текстов — предлагаемая редакция для проверки владельцем.

## Сеть облачной среды
Команды start, dev и telegram:chat-id используют поддерживаемые флаги Node.js 24 --use-env-proxy и --use-system-ca: HTTPS-запросы идут через прокси среды с проверкой системных сертификатов. Без флагов прямое соединение в этой среде отклоняется. TLS-проверка не отключается.
