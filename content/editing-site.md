# Как редактировать сайт и размещать отзывы

Для Александра. Обновлено 21 октября 2026 года.

Сайт: https://siteshopwork-dk21.vercel.app

Теперь отзывы и основные тексты находятся в двух отдельных файлах. Их можно менять прямо в браузере GitHub. Полноценной панели управления на самом сайте пока нет: сохранение происходит через GitHub, затем Vercel автоматически выпускает новую версию.

## 1. Добавить первый отзыв

1. Войдите в GitHub под владельцем репозитория `alextihonoy1981-byte`.
2. Откройте [редактирование отзывов](https://github.com/alextihonoy1981-byte/Site_shop_work/edit/main/site/content/reviews.json).
3. В файле уже есть пустая запись. Заполните значения в кавычках:

| Поле | Что вписать |
| --- | --- |
| `id` | Уникальное короткое обозначение, например `review-1`. У разных отзывов оно не должно повторяться. |
| `published` | `false` — скрыт с сайта. `true` — опубликовать после заполнения и проверки. Эти слова пишутся без кавычек. |
| `author` | Реальное имя автора, которое он разрешил опубликовать. Обязательно. |
| `context` | Компания, должность или сфера бизнеса. Необязательно: можно оставить `""`. |
| `text` | Настоящий согласованный текст отзыва. Обязательно, до 3000 символов. |
| `service` | К какой услуге относится отзыв. Необязательно. |
| `sourceUrl` | Публичная HTTPS-ссылка на оригинал, если он есть. Необязательно: оставьте `""`. Не вставляйте личные приглашения и ссылки с секретами. |

4. Убедитесь, что автор разрешил публикацию текста, имени и компании. Пример и черновик не должны выдаваться за реальный отзыв.
5. Замените `"published": false` на `"published": true`.
6. Нажмите **Commit changes…**.
7. В описании изменения напишите, например, `Добавлен отзыв клиента`.
8. Для непосредственной публикации выберите сохранение в ветку **main** и подтвердите **Commit changes**. Если хотите предварительную проверку, сохраните в новую ветку, посмотрите Preview и затем объедините Pull Request в main.
9. Откройте Vercel → **site_shop_work-dk21 → Deployments** и дождитесь **Ready** у новой публикации.
10. Откройте [раздел отзывов](https://siteshopwork-dk21.vercel.app/#reviews) и обновите страницу.

Отдельно нажимать Redeploy при обычном изменении этого файла не нужно: публикация из `main` запускается автоматически. Нужен новый успешный deploy, а не только сохранённый текст в редакторе.

Пока опубликованных отзывов нет, раздел показывает приглашение поделиться отзывом через Telegram. На сайте нет вымышленных имён, рейтингов, звёзд или результатов клиентов. После первой публикации приглашение заменяется карточками отзывов; ссылка для обратной связи остаётся под ними.

## 2. Образец записи

Это шаблон, а не настоящий отзыв. Замените значения данными реального автора и только затем включите публикацию.

```json
[
  {
    "id": "review-1",
    "published": false,
    "author": "ИМЯ АВТОРА",
    "context": "КОМПАНИЯ ИЛИ СФЕРА БИЗНЕСА",
    "text": "НАСТОЯЩИЙ СОГЛАСОВАННЫЙ ТЕКСТ ОТЗЫВА",
    "service": "НАЗВАНИЕ УСЛУГИ",
    "sourceUrl": ""
  }
]
```

Для второго отзыва скопируйте только объект между `{` и `}`, вставьте его перед завершающей `]`, разделите объекты запятой и измените `id` на `review-2`. Так можно добавлять следующие записи. Порядок записей в файле определяет порядок карточек на сайте.

```json
[
  {
    "id": "review-1",
    "published": false,
    "author": "ИМЯ ПЕРВОГО АВТОРА",
    "text": "ТЕКСТ ПЕРВОГО ОТЗЫВА"
  },
  {
    "id": "review-2",
    "published": false,
    "author": "ИМЯ ВТОРОГО АВТОРА",
    "text": "ТЕКСТ ВТОРОГО ОТЗЫВА"
  }
]
```

Не заменяйте весь файл образцом, если в нём уже есть нужные отзывы. Необязательные `context`, `service`, `sourceUrl` можно оставить пустыми или не добавлять.

### Особенности текста

- Текст пишется между обычными двойными кавычками `"..."`.
- Для цитат внутри текста удобнее использовать русские кавычки `«...»`. Обычные двойные кавычки внутри значения требуют записи `\"`.
- Новый абзац внутри отзыва обозначается `\n\n`.
- Не ставьте запятую после последнего поля перед `}` и последнего отзыва перед `]`.
- Если хотите временно скрыть отзыв, измените `published` на `false`. После успешной публикации сайта он исчезнет из карточек.
- Чтобы убрать его из текущего файла, удалите объект и поправьте соседние запятые. История Git может сохранять предыдущие версии.

Репозиторий сейчас публичный: даже записи с `published: false` доступны в его исходниках. Этот переключатель скрывает отзыв **на сайте**, но не делает файл в GitHub конфиденциальным. Сохраняйте только согласованные для открытого размещения данные.

## 3. Изменить основные тексты, услуги и контакты

Откройте [редактирование основных текстов](https://github.com/alextihonoy1981-byte/Site_shop_work/edit/main/site/content/site.json).

| Раздел файла | Что меняется |
| --- | --- |
| `location` | Географическая подпись над первым экраном. Другие упоминания географии и метаданные редактируются отдельно. |
| `audience` | Подпись об аудитории над первым экраном. |
| `hero.title`, `hero.subtitle` | Главный заголовок и его вторая строка. |
| `hero.intro`, `hero.description` | Вступительный текст. `\n` обозначает перенос. |
| `hero.button`, `hero.note` | Подпись основной кнопки и пояснение под ней. |
| `contacts.telegram` | Публичная ссылка для посетителей: контакты, прямые ссылки формы, приглашение оставить отзыв. |
| `contacts.phone` | Публичный номер в контактах и подвале. Ссылка для звонка формируется автоматически. |
| `services` | Список услуг: у каждой `title` и `description`. Порядок соответствует сайту. |
| `faq` | Вопросы и ответы: `question` и `answer`. Поисковые FAQ-данные обновляются вместе с видимыми ответами. |

Порядок тот же: измените нужные значения → **Commit changes** в `main` → дождитесь **Ready** → обновите сайт.

Меняйте текст внутри значений, сохраняя имена полей и структуру. Не нужно удалять файл или создавать новый репозиторий.

**Публичный Telegram-контакт и получатель заявок — разные настройки.** Изменение `contacts.telegram` не меняет `TELEGRAM_BOT_TOKEN` или `TELEGRAM_CHAT_ID`: они находятся в защищённых настройках Vercel. В публичные JSON-файлы токены и серверные ключи не вставляйте.

## 4. Где редактируется остальная информация

| Что нужно поменять | Где |
| --- | --- |
| Текст других блоков главной страницы | `site/app/page.tsx`. Здесь есть разметка: если не уверены, дайте мне конкретную правку. |
| Название и подпись в шапке/подвале | `site/app/ui.tsx` и `site/app/page.tsx`. Переименование бренда лучше делать согласованно во всём сайте. |
| Название страницы в браузере, описание для поисковиков | `site/app/layout.tsx` |
| Цвета, размеры, отступы | `site/app/globals.css` |
| Условия обработки данных | `site/app/privacy/page.tsx`, сведения оператора — `OWNER_NAME` и `OWNER_CONTACT` в Vercel |
| Основной домен | Vercel Domains и переменная `SITE_URL`, затем новая публикация |
| Токены Telegram, ключ базы, включение приёма | Vercel → Settings → Environment Variables, после изменения — Redeploy |

На сайте сейчас нет кнопки входа владельца и редактора поверх страницы. Редактирование через GitHub не требует отдельного пароля сайта и не добавляет новую публичную форму ввода отзывов. Посетители могут отправить отзыв вам в Telegram, а размещение выполняете вы после согласования.

## 5. Если после редактирования ничего не изменилось

1. Убедитесь, что сохранили изменение через **Commit changes**, а не только напечатали его в редакторе.
2. Проверьте, что изменение попало в `main`, а не осталось в другой ветке/необъединённом Pull Request.
3. В Vercel выберите именно **site_shop_work-dk21** и соответствующую новую публикацию.
4. Дождитесь **Ready**. Если статус **Error**, откройте Build Logs: сообщение может указать пропущенную запятую, пустой текст опубликованного отзыва, повторяющийся ID или неверную ссылку.
5. Исправьте файл и сохраните новый коммит. Предыдущая успешная версия обычно продолжает работать при неудачной сборке.
6. Для отзыва убедитесь, что `published` равно `true`, а `author` и `text` заполнены.
7. Откройте правильный адрес сайта и обновите вкладку. Для проверки старого кеша можно открыть новую вкладку инкогнито.

Если нужна помощь, сообщите, какой файл редактировали, время изменения и ошибку Vercel без ключей и клиентских персональных данных.

## 6. Самый простой способ работать со мной

Можно прислать согласованный отзыв и написать:

> Размести этот отзыв на нашем сайте. Автор: [публичное имя]. Компания: [если согласована]. Услуга: [название]. Текст: [согласованный отзыв]. Оригинал: [публичная ссылка, если есть]. Публикация согласована. Проверь на телефоне и опубликуй.

Для текста сайта:

> В блоке [название] замени [старый текст] на [новый текст]. Остальной стиль сохрани. Проверь и опубликуй.

Я внесу изменения в те же файлы и проверю публикацию. Для вашей самостоятельной правки достаточно GitHub и проверки статуса Vercel; компьютер с установленным Node.js не нужен.
